# 新电脑首次衔接 Prompt

先在开发助手中打开本仓库根目录，再完整复制以下代码块。可以保留默认“本次需求”，也可以直接换成开发或分析任务；路径不清楚可留空。日常后续需求见文末短版。

```text
你正在新电脑接手 mem-you-service。请以当前仓库、现行合同和本次需求为依据恢复项目上下文，然后完成本次工作。不要假定能访问原电脑、旧聊天或之前开发助手的本地记忆。

一、先核实现状
1. 确认工作目录、仓库远程、当前分支/HEAD、工作区修改和最近提交。输出远程时隐去凭证；保留现有修改，不自动reset、覆盖、切分支或全量重建。
2. 读取根AGENTS.md、docs/cross-computer-handoff.md、docs/README.md、docs/spec-v1/README.md及00边界文件。然后按本次任务读01/02/03、04和06的适用部分；涉及首发取舍时读07。
3. 检查实际源码、依赖manifest/锁文件、配置样例、迁移、脚本、测试和报告是否存在。2026-11-02最新交接为V1.2修订2设计及agent-service宿主接入细化，没有记忆服务实现或运行验收；这是有日期的快照。若现在已有新实现，以实际文件/提交核对进度，不退回旧状态。
4. 若存在.local/context.md，先读取其中非敏感的路径映射，再定位外部项目。Agent仓库根、apps/agent-runner宿主和packages/core运行内核分别核对，不能沿用旧电脑绝对路径。不扫描真实.env、凭证文件或整个个人目录，不把密钥、真实用户数据带进输出或Git。

二、恢复必须遵守的设计边界
- docs/spec-v1/是唯一现行开发合同：00–04为核心；06中原生身份/生命周期共享细则适用于首发A，启用历史扫描和任务控制时再增加扩展要求。05/07是决策说明；research/及两份旧方案是历史依据，不能从中拼接废止接口。
- MemoryService保存有来源、有版本、可撤回的来源镜像、记忆与证据，负责召回与失效。正式记录、产品时间线和精确统计归产品后端；Agent负责理解、工具及可靠journal。模型自称“已保存”不是正式回执。
- 首发A是HTTP核心和一个点滴full_lifecycle适配器，含可靠输入、稳定原生origin、同身份重送、基础派生/人工slot保护、更正、持续删除/撤权、消费者清理和旧备份恢复门禁。关闭history不免除原聊天生命周期责任。
- B是可选的接入后已登记会话有界手工MySQL补采和部分派生修复。自动发现/巡检/重抽、接入前历史bootstrap、MCP及更多适配器、search/facts、图、自动摘要和P1等按能力后置。不要把所有API目录当成首发任务。
- 实时与补采共用稳定origin及原计划source/group；不靠正文相似度、随机ID或抢latest CAS覆盖去重。owner与陈述对象、报告与推断、各类时间分开；未知单位、主体、更正目标不猜。
- 权限、CAS/幂等、读屏障、人工保护、删除与恢复不能因裁剪被省略。所有入模证据包括工具补查都登记依赖；逻辑失效、物理清理和消费者清理分别回执，旧备份不能复活已删除内容。
- 未知业务执行/付费调用结果先核对，不盲目换key/换run重调。未实现能力明确unsupported；空召回、降级、未追上和失败不能混同。
- 规格中的性能/效果/容量是验收目标，合同矩阵是待执行用例。假模型或服务测试不替代真实产品集成、中文效果、P0及恢复报告，不伪造验证结果。

三、按需恢复外部依赖
1. 本仓库：https://github.com/zhgqwx-del/mem-you-service 。现有Agent另在 https://github.com/zhgqwx-del/agent-service ，原审计commit为5d38b2cd6307aab9c8dec2c475b1bebf886d8283；2026-11-02按ca24972f6094bbf48658e60113d19112290e2544复核宿主接入，范围及缺口见交接第14节。仅当任务需要实际集成或复核时再定位/获取Agent项目，并读取它自己的AGENTS/README/manifest。当前版本不同需重新核对，不机械沿用旧行号或重置工作项目。
2. 原始点滴demo HTML和旧05记忆层设计不在本仓库，原路径、字节数与SHA-256在交接说明中。按新电脑实际路径映射；缺失时可用已保存审计继续独立工作，但标明未复核原文件。demo mock不是真实运行数据。
3. research/里的本地/tmp快照与原电脑绝对路径不是当前依赖。需要复核某个结论才按官方仓库及固定commit重新取得，不默认最新main等同旧证据，也不装齐所有研究框架。
4. 当前没有已交付的记忆服务数据库或现成评测数据包可恢复。测试先用明确标记的合成/获授权脱敏fixture，区分已有数据与目标数据集。若后续已有数据库，再按实际迁移/恢复文档处理，并验证授权与删除控制日志，不能只恢复旧主库。
5. 缺少外部源码、数据库、模型、预算或配置时，只询问真正阻塞本次任务的最小信息，继续完成其余独立部分。没有实际产品接入就明确写“夹具验证”，不能报告端到端已通过。

四、执行本次需求
先简短说明已确认状态、会影响本次工作的缺口和准备执行的范围，然后直接推进。只做分析时不顺带建工程；请求开发时完成可审查的修改及适用验证，不停在计划或能力说明。

若本次是从零开始D1，先按04交付顺序冻结A能力清单，建立可重现工程、依赖锁、无密钥配置样例、数据库迁移和必要的本地依赖；再实现grant/身份、schema、source/op、CAS、单一inbox/屏障、最小取证及原断言关联，用假RecordService、input evidence及稳定operation夹具执行适用合同测试。具体字段与通过条件查01/02/04，不由此Prompt重新定义。D1完成不代表D3删除闭环、完整接入或A首发完成。

运行环境和命令以实际manifest/锁文件/脚本为依据。不存在的命令明确说明；首次实现时选择与合同兼容的版本、记录理由并固定，补启动/测试/迁移说明。不因原电脑缺环境而装全部研究依赖。

用户本次需求与后续明确授权决定执行范围；常规可逆本地修改和验证可直接完成。没有相应授权时不接入生产、不迁移真实用户数据、不调用真实付费模型，不自动发布、推送或重建共享环境。若用户已给出具体预算或授权，沿用它，不重复确认。

结束时说明完成了什么、实际执行了哪些验证及结果、仍缺什么，并同步更新交接中的实现状态、可复现命令与未完项；合同变更同步相应分册和验收。标明尚未提交/推送的修改，别让下一台电脑误以为已经能拉取。

五、本次需求与本地信息
本次需求：先完成环境与上下文核查，列出可以立即开展的工作和实际缺口；暂不创建服务实现。若我在下方追加了更具体需求，则直接按该需求推进。
本仓库路径：使用当前工作目录。
AGENT_SERVICE_ROOT：优先使用.local/context.md中的本机映射并核对HEAD；没有映射时仅在本次任务需要时定位或获取。
AGENT_RUNNER_ROOT / AGENT_RUNTIME_CORE_ROOT：使用本机映射，缺省在已核对仓库内定位apps/agent-runner及packages/core；前者装配运行服务，后者提供会话/turn/模型工具循环。
DEMO_HTML：未提供，可缺失。
LEGACY_DESIGN_MD：未提供，可缺失。
LEGACY_DESIGN_RTF：优先使用本机映射；已有RTF时可提取纯文并对照交接摘要，不把临时文本路径当持久依赖。
已有本地环境/数据：未知，先核对当前仓库可见配置样例和说明，勿读取密钥值。
验收期望：与本次需求对应的现行合同；未运行项明确列出。
额外约束：无。
```
