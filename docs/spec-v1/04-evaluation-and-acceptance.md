## 1 V1 检索实现基线

### 1.1 索引与来源

来源修订、记忆修订及访问/失效门禁是读取依据；全文和向量只是候选索引。先按 tenant/owner、about entity、域、有效时间和策略缩小可见范围，候选合并后再检查源版本及授权，不能全局近邻后让模型过滤其他人的内容。

文本标准化只作用于检索副本：NFKC、英文小写、连续空白折叠、注册词典别名。保留原文和映射，不能把标准化后的字符下标当作原文证据。中文词法采用可固定版本的分词器加字符 bigram 兜底，保留数字、单位、否定词、人名和药名，不用通用 stopword 表删掉“不、没有、不是”。

默认实验基线使用 jieba 搜索模式及冻结的词典、BM25 的 k1=1.2、b=0.75，按用户授权内语料计算候选。其实现可用同库倒排与词项统计，也可用满足相同合同的检索组件，不把 PostgreSQL 内置排序直接称作中文 BM25。[分词器一手说明](https://github.com/fxsjy/jieba)

Dense 对照默认使用 BGE-M3 的 1024 维归一化 dense 表示与 cosine 精确排名，固定模型 revision 和 tokenizer；只使用其 dense 输出，不假设其他检索模式已接入。该选择是可重现基线，不是宣称其在本场景最优。[模型卡](https://huggingface.co/BAAI/bge-m3)

实际模型、词典文件摘要、维度、归一化、距离与模型服务修订写入 release manifest。更换模型允许，但必须建立新 representation/index generation、重跑效果和删改回归后切换；公共 API 不暴露向量坐标，不能把不同模型向量直接比较。

### 1.2 查询策略

查询 cue 来自当前输入、已选主体、已确认字段、purpose 和显式时间/实体。V1 不为每个请求增加 LLM 意图分类、查询扩写、reflect 或长摘要生成。主 Agent 可以通过后续 search 调用重述查询。

| 通道 | 初始上限 | 规则 |
|---|---|---|
| 近期原始来源 | 24 个候选 | 当前主体最近7天；resolve_reference可再看最近24个授权来源。严格时间查询不越窗充数 |
| 中文词法 | 40 | BM25、别名、字面实体与单位；保留命中字段与来源 |
| Dense | 40 | 授权范围内精确cosine；索引未就绪时明确缺口 |
| 实体和类型化值 | 20 | 注册字段匹配及时间过滤；数字接近本身不是同一事件证据 |
| 一般偏好与未完信息项 | 10 | 最多6个一般偏好、4个未完项；来源、scope与有效期均满足；必要约束另行完整核验 |

普通通道合并候选硬上限160，按来源版本与确定性身份去重。另从本次授权及purpose范围完整核对适用的必要约束，不以相似度、6项偏好或160候选上限裁掉；不把未经确认的普通偏好升级为必要约束。一个 source_group 含多个不同外部事件时，不能压成一个事件；展示可以折叠同组上下文，但仍保留多个 external_record_ref。

对词法、dense、实体、近期通道采用 RRF，k=60，权重初值分别1、1、1.2、0.5；同分按稳定ID。适用显式约束不靠普通相似度竞争：先检查其作用范围，再作为行为约束保留。RRF只融合排名，不表示事实概率；来源权威用于陈述标签、冲突处理和选择，不把所有user_reported证据一概排除。

### 1.3 按 purpose 使用历史

| purpose | 优先用途 | 禁止自动推导 |
|---|---|---|
| respond_to_record | 单位/主体消歧、相关近期事件、当前明确偏好、避免重复追问 | 仅凭最近记录为体重就把未知数值永久认定kg；把相关性写成病因 |
| answer_history | 用户明确条件内的可追溯证据与分页补查 | 把top-k数量说成总次数；用记忆投影替产品账本 |
| resolve_reference | 当前输入与近期来源的候选关联、必要缺口 | 把最相似候选直接作为更正目标提交 |
| assist_correction | 显式目标引用、上轮实际用过的证据、当前版本与冲突 | 自动覆盖多条相似事件，或将真正新事件判为重复 |

本次输入及同 source_group 默认排除在历史证据之外；其内容仍作为当前输入交给 Agent。查询中“去年”“上个月”以明确时间窗过滤，不施加统一近期衰减。未知发生时间不伪装落入指定月份，返回 `time_uncertain` 缺口；recorded time 和event/valid time的解释见数据/API合同。

### 1.4 有用性门控与预算

候选只有满足下列一种明确用途才交付：消歧、有效约束、工具参数证据、用户显式查询、前次未完问题、当前问题确有帮助的关联。仅仅同主题、已解决、近期反复出现而无新作用、用户已关闭的反馈来源应被抑制。未知关联保留为问题，不改写为事实。

默认预算1200 tokens、8 items，上限4000 tokens、20 items。预算包含 canonical_injection 中的正文、来源、时间、不确定性和gap；不包含仅供服务诊断的候选列表。服务用已注册tokenizer计数；未知模型用明确标记的保守估算，并附32KiB正文硬限。不能以“估算”绕过字节限额。

优先保留明确且适用的当前约束，再保留本次必需证据，其次一般偏好与补充材料。无论条数是否满都允许空包。若必要约束及其最低元数据无法装入token_budget、max_items或32KiB，返回422 `TOKEN_BUDGET_TOO_SMALL`，details.limit_kind分别为token_budget/max_items/content_bytes，不发布可用bundle；一般补充证据超预算可截断并报告gap。约束完整性、适用性或当前性不可核验时返回503 FRESHNESS_UNAVAILABLE，到deadline为504 FRESHNESS_TIMEOUT，allow_safe_partial也不能跳过。Agent不得在不知道关键约束是否完整时执行依赖这些约束的动作，可提高预算补查或追问。

同一 source/group 的普通重复片段最多交付2项；存在不同事件、明确对比或更正证据时可例外，并记录选择原因。禁止按“同主题且时间邻近”合并业务事件。最终检查来源头、记忆版本、generation和policy；检查失败按API失效规则处理。

### 1.5 降级规则

| 情况 | 服务返回 |
|---|---|
| 当前权限和read_after满足，所有计划通道正常但无适用证据 | empty，含查询范围；不表示用户从未记录 |
| 计划通道不可用/落后，但其余安全通道仍可用 | allow_safe_partial才可degraded，明确缺失通道；require_planned_channels返回503 PLANNED_CHANNEL_UNAVAILABLE，到deadline则504 DEADLINE_EXCEEDED，均无历史正文/usable bundle |
| 权限无法校验、来源已撤回、read_after未满足 | 错误或未追上；不得交付旧历史正文作为partial |
| 必要约束及最低元数据无法容纳预算 | 422 TOKEN_BUDGET_TOO_SMALL；提高预算或停用依赖动作 |
| 必要约束完整性、适用性或当前性不可核验 | 503 FRESHNESS_UNAVAILABLE，到deadline为504 FRESHNESS_TIMEOUT；不交付可用bundle，不能降为普通通道缺失 |
| 一般证据超预算或上游模态未识别 | 可用的安全部分加gap；依赖缺失信息的动作停用/追问 |

deadline包含鉴权、屏障等待、各路召回、组装和最终有效性检查。初始1800ms，上限3000ms；剩余时间不足则取消未完成通道，不无限重试。超时不会改变已提交的source或memory写入结果。

## 2 写入富化与归纳策略

同步事务负责保存来源/版本、确认字段、最小可读数据、旧依赖失效和回执。已有注册结构化字段直接校验并形成镜像取证投影，不先变成自然语言再抽取。

普通自由文本异步抽取采用每owner最多8个来源微批，等待窗口初值5秒；模型输入预算6000 tokens，输出预算1000 tokens。单来源超预算时分块处理，保留精确来源版本和原文偏移；不得静默截掉后半段。批次只含同授权空间数据，不为提高批量率混入别人的记录。

抽取产出受注册 schema 校验；无来源、单位猜测、主语不明、语气错误或无依据推断不得晋升明确事实。用户“我担心…”保留担忧语义；模型建议不能成为用户已做。自动任务记录model/prompt/schema/slot/输入版本；同槽重试最多产生一个当前发布结果。

embedding 与抽取分离；任一路失败不抹掉已接受原文。后台回退初值1s、5s、30s，最多3次执行；只有可证明安全的错误才自动重试，权限错误、证据错误或版本过期直接隔离/废弃。所有付费embedding、抽取、摘要调用先持久登记稳定invocation和预算预留；发送后结果未知不进入这组自动重试，不因新run/新lease重复dispatch。安全重试仍单列attempt与可能费用，不承诺provider侧exactly-once计费。3次后进入人工可见的failed队列，保留源版本，修复后以相同逻辑slot显式重放，不重复发布。并发租约、取消准入和未知调用恢复以03/06为准。

V1不为所有用户预生成日周月季摘要。只维护小型来源支持的偏好/约束投影，以及在一个主题积累至少20条新来源或现存摘要超过4000 tokens时的预算化摘要任务；“至少20条”仅是触发后台计算的资源阈值，不决定是否允许查询、统计或保存重要事实。摘要是可替换导航，不是权威台账。显式偏好、更正与删除不等待此阈值。

自动episode summary为扩展能力：首发可关闭该任务，保留原文/明确记忆召回；上述触发、成本和摘要效果只在启用时验收。声明/显式偏好及约束的摄取、版本与使用不依赖自动摘要，也不要求先建设memory_relation图。

2026-10-28补充分层解释：按[00§4](00-boundaries-and-invariants.md#41-memoryservice内部逻辑分层)，抽取与启用的摘要属于L1内容派生，embedding/词法属于L2表示建设，前台预算选择与bundle属于L3读取编排；三者分别就绪，不能把摘要当作全部读路径的前置。小型画像采用有来源、可修订的偏好/约束及带标签归纳，不新增统一周更任务。将来启用周期或多级摘要时仍保留原始来源闭包，不能只留低层摘要作为不可回查的唯一依据；不从摘要项数或top-k计算正式生活统计。该说明不改变既定模型、RRF参数、摘要触发阈值或A/B/C能力范围。

## 3 数据集与实验固定方式

### 3.1 评测集

首版建立100个owner时间线，每个60–120条来源；50个开发集、50个封存测试集，至少600个测试turn，其中明确“不要使用历史”的负例不少于25%。同一owner及其改写/合成变体只进入一个集合。

每个测试turn必须保存历史前缀、新输入、主体与授权、上游确认/候选状态、允许行为、必需/可选证据、禁止推断、预期工具与目标版本、允许的追问、期望页面状态。查询只提供当时已知的来源，不使用未来更正或后续摘要泄漏答案。

来源采用人工编写及获授权脱敏样例；合成仅扩充难例，不代替真实分布。语音/图片先用固定转写/OCR结果测试记忆合同，再用独立识别测试集评价识别误差的影响。记忆服务不因媒体测试失败而被要求实现识别模型。

至少包含本人、两个宝宝、同名他人、跨日/跨时区、kg/斤、不同币种、否定/愿望、两次真实相同事件、来源纠正、产品已提交但通知延迟、已删内容、源文本中的注入指令、scope混合片段和仅MCP宿主。

### 3.2 版本清单

每次验收冻结服务构建摘要、数据库迁移版本、数据文件摘要、grant与schema快照、embedding/tokenizer/dictionary/model/prompt修订、策略参数、候选框架commit、reader模型、judge版本和硬件。纯模型比较使用相同reader与历史权限，不以更大的隐藏token预算取得优势。

报告必须分别给出前台、后台、主Agent和产品工具费用；上游模型真实收费需具名预算，未获预算的阶段只运行受控依赖测试。当前设计文档不授权真实模型或生产请求。

### 4.2 E 主体与授权

一个账户拥有self、baby_a、baby_b。输入中明确baby_a在昨晚03:00喝100ml、早上07:00喝120ml，中间换一次尿布。三个正式事件共同来源，日期由上游确认/澄清；缺日期不自动替换成服务器今天。baby_b和self的相同数值不是同一主体。

仅baby_b的grant对baby_a来源、片段、摘要、外部条目ID和隐藏命中数量均不可见。原始混合输入about_entity_id=null时，窄主体grant不读取全文。一个获授权Agent可接收记录上下文；另一个只有memory读权限的Agent可查证据，但不能写产品条目。

### 4.3 F 来源更正 擦除与缓存

1. 上游OCR候选108.4斤被用户确认，产品记录明确为108.4斤，标准值54.2kg及转换规则由产品提供；Memory镜像其证据。无昨日值时Agent不造昨日对比。
2. 创建bundle b1后更正来源，检查b1无论未过期、命中过缓存、同key重放或被operation最终响应引用，都不能重新交付失效值。
3. 对source_group执行erase，local_enforced只在本服务失效与耐久擦除日志可核对后成立；后台清理与consumer状态分别显示。
4. worker持有旧source_version的任务此时完成，必须superseded而非发布。重放旧Outbox、旧索引代、旧备份也不得复活来源。
5. full_lifecycle消费者清空受影响prompt/摘要/反馈缓存再ack；未ack消费者不因租约过期自动算complete。tool-only宿主显示不可证明的远端状态，后续工具读仍被拒绝。

### 5.5 记忆触发偏好与事件身份的固定变体

## 6 效果指标与发布门槛

### 6.1 对照组

固定主模型、工具、可见历史和费用报告，比较：无长期记忆；近期窗口；小owner全量原文；原文混合检索；混合检索加有效偏好/结构化证据。Hindsight或Mem0可作为选型扩展对照，MemOS可仅对照adapter与纠错；第三方框架对照不作为首发上线前置，不要求同时部署多个引擎。

全量原文组可以作为小数据强基线，但报告其token与延迟，不隐藏更高预算。效果和成本一起决定选择；若复杂方案没有超过近期窗口，不应以框架知名度跳过这一结果。

### 6.2 指标

| 指标 | V1发布门槛或规则 |
|---|---|
| 证据引用完整性 | 所有交付记忆均能解析到授权的精确来源版本；结构校验100% |
| 关键证据召回 | 1200 token预算下测试集required evidence recall≥90%；明确ID/实体取证≥98% |
| 时序/更新 | 时间与有效状态样本正确率≥95%；已applied删除、授权、CAS错误为硬门禁零容忍 |
| 内容忠实性 | 人工判定无支持的新事实≤1%；伪造产品保存、主体串线、将候选诊断化均不得出现 |
| 必要澄清 | 主体/单位/目标确不明样本中正确待补/追问≥95% |
| 无必要追问 | 已确认picker及字段充分样本中不必要追问≤5% |
| 无关或重复使用历史 | 负例和频控场景误用率≤5%，同时报告不使用历史的正确率 |
| 交互收益 | 相对无记忆组盲评偏好率≥60%，按owner聚类95%区间下界>50%；相对近期窗口报告差值，区间不能显示明显退化 |
| 工具与统计可信 | 金标准中的目标条目、单位、版本、幂等与产品指标全部正确；不得从top-k宣称完整总量 |

这些是本项目预设验收目标，不是文献成绩。若未达到目标，调整策略、实现或首发范围并重跑；不能在同一结果上静默降低门槛。真实用户试点另看满意度、纠正率和关闭反馈率，不能只靠LLM judge。

证据、数值、授权和回执使用确定性oracle；主语/语气/有用性由双人盲评加分歧复核，LLM judge仅辅助。抽样评审同时看没有返回的关键证据，避免只评模型已经引用的结果。

### 6.3 定位问题的分项报告与可选对照

以下细化既有评测的错误归因；可选消融只在需要定位策略收益或选型时执行，不要求首发额外实现全部候选pipeline，不增加发布分数门槛。报告仍绑定同一数据前缀、授权、reader、预算和实际版本，区分离线对照与可发布能力。

- **召回与选择**：可分别比较中文词法、dense与融合，明确近期/实体/偏好通道是否保留；分purpose报告required evidence在候选、融合和最终预算交付阶段的覆盖，避免将门控或预算淘汰误判为embedding漏召回。用固定fixture核对01§9.3的trace能解释最终交付，评分不代表事实概率；有相应标注时才附报MRR/nDCG等排序指标。
- **少历史用户**：按当时获授权且可使用的历史前缀分组，单列空历史、少量和较长历史下的召回、空包、澄清及误用；这是效果诊断，与§7的缓存冷owner不同，不增加API历史数量字段或通用条数准入门槛。G13验证第一条适用偏好/约束也能生效。
- **时间错误**：分别定位上游时间表达识别/区间归一与Memory对已确认Occurred的过滤/排序错误；按相对、近似、未知、跨日/跨时区样本报告正确区间、精度及保留unknown/澄清的结果。只有边界均有定义且可比较的有限区间才附报边界误差或IoU，开放区间、日级和未知精度单列；抽取F1不能代替归一化准确率。不因此指定JioNLP、新增occurred_conf或前台LLM兜底。
- **富化收益**：沿用§6.1原文与偏好/结构化证据对照；若比较不同抽取批次或启用摘要，另报完整费用、可见滞后、引用忠实性和交互收益，不能用晚到的未来更正或更大隐藏上下文取得优势。

#### 6.3.1 反馈诊断与修复报告

对固定夹具中的失败或有合法来源的纠正反馈，先比较当时允许的结果与实际路径，再按下表归因。各类可以同时成立；证据不足时标明未定位，不凭最终回答倒推出中间步骤。L0原文可经合法通道直接检索，writer不是所有读取的前置；仅在相关候选形成确实影响本次任务时归因writer。

| 诊断类别 | 用既有证据判别 | 修复与复验方向 |
|---|---|---|
| 错误skip或不适用历史 | 对照03§2.1的持久prepare/skip决策、当前主体和可信确定性条件；分别判断应prepare却跳过，以及正确prepare后本来没有适用历史 | 修适配器决策或夹具预期。正常空包、主动不使用无关历史可为正确结果，不以增加检索次数或填满预算作为优化 |
| writer候选错误 | 比较精确来源前缀、候选内容、确认/范围/出处及发布结果，分开记录候选遗漏/无依据新增、服务拒绝/隔离与发布后错误 | 在§6.4.1固定条件下复核prompt/schema使用或writer策略；服务拦截、原文直检或reader补救不能抹掉候选错误，也不能以抽取成功冒充实际交互收益 |
| 索引或召回遗漏 | 在当时授权且有效的必需证据中，核计划通道是否就绪、覆盖状态及通道候选引用 | 区分索引/派生未就绪、过滤错误与检索未召到，按§1.5报告降级/错误；不把本来无权或已失效的材料列为应召回证据 |
| 融合、门控或预算淘汰 | 证据已在合法候选中，但未进入最终交付；查融合位置及用途、重复展示、约束和预算的保留/排除原因 | 先判断淘汰是否正确，再选少量策略对照。普通无关证据被抑制可为正确结果，必要约束遗漏或放不下须按原错误合同处理，不能靠放宽预算门禁修分数 |
| reader或工具使用错误 | 正确证据已实际入模，但回答、澄清、工具参数或目标版本错误；检查当前输入、实际工具回执与证据是否被正确使用 | 修主Agent提示、工具定义、应用编排或代码，并重跑对应基线与回归；交付或引用不等于正确使用，未知业务执行结果仍先查可信回执 |
| 来源当前性、权限或失效控制错误 | 检查当前授权/版本、barrier、bundle校验、失效流与消费者清理；区分按合同拒用和继续使用旧/越权材料 | 修复控制链并按既有C/A项复验。正确拒绝是安全结果，非法交付是硬门禁失败，二者均不能并入普通相关性误差或用平均任务得分抵消 |

报告复用01§9.3的最小审计和已有产品/Agent journal，保留固定样本与trace的关联、版本/授权/历史前缀摘要、期望与实际路径、当前可核验的候选/交付/实际入模引用和排除原因、归因依据或未定位项、修复对象及所复跑的既有用例/结果。以上是评测报告内容，不是新增服务字段、持久对象或公共debug接口；缺少某阶段证据时如实标缺，不反向从正文补造可信依赖。

诊断只保存当前授权内允许审计的最小元数据，默认不采集全量Trace、原文或完整prompt，不记录越权候选ID、隐藏数量、凭证及媒体URL；抽样调试仍沿01/04的独立权限、短保留和擦除规则。反馈先决定补夹具、改提示/检索、工具定义或代码。从反馈中形成用户新披露时，须具备真实用户来源并按原写入合同处理；可信外部回执仍走既有镜像路径。评测标签、人工判读、回答及再次引用不回灌成用户记忆，也不自动发布程序指令或技能。

提示/策略调优使用开发集，封存测试只用于冻结后的验证；修复前后固定可比的模型、来源前缀、权限与预算，变更控制变量时分别重跑适用基线。该诊断细化既有报告，不要求新增遥测平台、真实用户轨迹采集、自动学习或C阶段维护任务；A的既有审计和协议硬门禁继续适用。

### 6.4 上下文敏感性与可替换writer对照

本节将长上下文研究转为适用的诊断设计；G14/G15选取固定代表场景，按失败再扩展，不要求A跑完所有长度×位置×干扰组合，不新增分数门槛或提高API预算上限。论文对应模型和任务不能代替本项目固定reader上的结果，研究依据见[上下文退化与学习策略](../../research/papers-frontier-notes.md#11-2026-10-28-上下文退化与学习策略补核)。

| 诊断 | 控制与报告要求 |
|---|---|
| 正确证据与干扰 | 固定任务、事实前缀和正确证据，分别增加当前获授权的无关片段、相似但不同主体/时间的陈述及重复材料；区分候选覆盖、实际入模覆盖和reader用错。scope外材料须在授权门禁被拒，不能为效果测试变成合法注入 |
| 长度、位置与任务说明 | 在既有合法Memory预算内对比，并单列当前输入、聊天历史、工具结果及Memory各自token量。证据前/中/后位置与可信任务说明位置分开控制，保持system/data权限边界；每个变体生成独立可追踪输入或合法新包，禁止修改冻结canonical_injection仍沿用旧hash |
| 历史污染及失效 | assistant自述、旧工具正文、重复摘要不晋升为新用户披露。更正/删除后的旧主张、bundle和压缩缓存按C06/C18/C20/C22及A08/A10阻断/清理；这类硬门禁不以reader平均分抵消，不能把已失效正文重新交付来制造长度实验 |
| 相关证据诊断上界 | 可增加人工选择相关证据的reader组，明确标为oracle、记录其人工条件与token费用；同时保留真实检索及§6.1基线，不能把oracle分数算作服务召回或部署能力 |
| writer与reader隔离 | 选型时固定数据/时间前缀、授权、reader、检索器及预算，只更换可用writer模型/策略；分别报告语义/数值/出处保持、遗漏、无依据新增、重复/人工保护冲突、更新语义、存储增长、发布滞后和真实费用。原来源保存完整性与派生压缩率分开，不能以压缩奖励丢来源；特殊writer、图或后台归纳仅在声明启用时比较，不为此先安装全部框架 |

#### 6.4.1 写入策略的可选对照

需要定位写入质量或选择writer时，在上述隔离条件下选取少量代表变体，不要求首发实现全部策略。先固定writer模型只比较提示，再固定提示的任务语义比较writer模型；reader、检索器、来源/时间前缀、授权、工具和预算上限保持一致，报告各组实际消耗与发布滞后。若另换reader，须分别重跑其无长期记忆及§6.1适用基线，不把reader增强归因于写入策略。

| 变体 | 控制内容 |
|---|---|
| 基础抽取 | 以现有注册schema、证据及发布规则生成候选，作为可运行基线 |
| 任务用途指引 | 在同样硬约束下增加写入当时已知的产品任务/用途说明，检验是否减少无用派生或关键遗漏 |
| 候选选择空间 | 在相同schema和硬约束内允许writer更自由地选择可选派生内容；不预设“只记失败”等通用显著性规则 |

各组可靠保存同一批应接收来源，显式记忆、必要约束和删除/撤权控制不参加显著性裁剪；选择空间不改变主体、单位、权威、CAS、人工保护及失效门禁。writer只获得写入当时可用的输入，不提供未来测试提问、金标准或后续更正；prompt选择使用开发集，封存测试集不用于迭代提示。可选摘要/复核仅在声明启用的实验中比较，不把其结果提前交付给历史前缀。

报告分别统计候选阶段的遗漏、无依据新增及主体/时间/数值/出处错误，服务拒绝或隔离的原因，发布后仍存在的错误，以及最终交互收益；不能让服务拦截或reader补救掩盖writer错误。人工抽样同时看未选中的关键证据，区分“交付过”“被引用”与经固定任务核验的正确使用。报告沿用§6.2的适用门槛和§7.3的费用口径，不增加新分数或放宽既有硬门禁。研究依据见[Anthropic记忆评估](../../research/anthropic-agent-memory-review.md#4-值得增加的评测设计)。

后续学习策略可使用有合法来源的纠正、过程及有用性标签，但“被引用”“最终回答正确”不自动成为写入正确的标签。源可靠保存、权限、CAS/幂等、连续屏障、人工保护和删除恢复是协议约束；学习组件不可将其改成可用奖励交换的动作。训练及用户轨迹数据治理另行设计，本轮不执行训练或新增真实调用。

## 7 性能 容量与费用验收

### 7.1 首发与扩展测评档

首发采用P0，避免在未知真实规模时先承诺百万级语料容量：1个API实例4vCPU/8GiB、PostgreSQL 4vCPU/16GiB/SSD、1个worker 2vCPU/4GiB，embedding资源单列。语料100个owner各1000来源，加2个重owner各10000，总计12万；普通owner固定分为95个warm池与5个预留冷启动池，另2个重owner独立成池。5分钟warmup＋10分钟正式阶段，读5RPS、写2RPS，沿用下方P1的endpoint、90%/5%/5%池流量比例、seed及开放到达规则（读200ms、写500ms计划一次）。首发未启用search时其读比例归context。控制请求与真实embedding仍计入资源和延迟，不能关门禁换成绩。

P0须通过下表相同延迟/正确性目标和恢复演练，只能据此声明P0档能力。P1是扩展容量验证，达到此流量/数据规模前再执行，不阻塞P0首发；生产实际峰值、数据保留量或部署资源超过所验档位时必须另行验证，不能把P0通过外推为P1或真实生产承载保证。

#### P1 固定负载

P1 是统一的开发压测档，不是实际业务规模预测或云部署采购方案：2个API实例，每实例4vCPU/8GiB；PostgreSQL 8vCPU/32GiB、SSD；2个worker实例，每实例4vCPU/8GiB。embedding/抽取服务单列其资源，不把GPU或外部厂商延迟隐藏在API资源里。

语料为2000个owner各3000条来源，另10个owner各30000条，总计630万来源；普通owner固定分为1900个warm池与100个预留冷启动池，另10个重owner独立成池；每条40–200汉字为主，另有16KiB长来源及多版本删改，10%含多个about entity。准备10分钟warmup，正式负载持续30分钟。固定seed为20261027，数据摘要、请求顺序、目标ID及变更版本全部进入manifest，同一次对照复用同一计划。

| P1请求组 | 固定速率与分布 |
|---|---|
| 召回读总量 | 总计50RPS，包含context 35RPS、search 15RPS；其中90%分给warm池、5%给预留冷启动池、5%给重owner池。池流量已含在50内，不代表5%的请求始终为冷首读 |
| 来源及变更写总量 | 总计20RPS：sync新增18、sync更正1、ordered_import 0.5、单来源erase 0.5；变更目标来自固定夹具且每次使用正确当前版本/稳定身份。不要把20全当新增后另算更正 |
| 屏障与失效 | 5%的召回读带已知write_token或external barrier；更正/擦除后安排针对目标的新读及旧bundle validate，独立记录安全结果 |
| 受控依赖与生命周期 | 普通性能阶段依赖正常、流无故意缺口；context使用预登记消费者及同一固定adapter配置，必需validate/heartbeat/change请求另计速率、CPU与延迟且不能关闭门禁。manifest须保存这些控制请求及注册/reset的完整编排计划 |

采用开放到达负载：召回读每20ms计划一次、变更写每50ms计划一次，按seed分配endpoint与owner；客户端不等待上一个请求结束再发下一个。延迟从计划到达时刻计算并单列客户端排队、服务处理和超时，避免压力越大反而测得越少。三个owner池互斥；warmup及正式写入/控制请求均不得提前预热预留池的读取缓存。该池每owner仅首读标cold，后续归warm，不重复伪称cold；重owner不当冷owner重复计数。报告实际冷首读样本数/占比、warm读和重owner读的延迟，不删除超时结果。

正式混合负载中的冷首读最多P0 5个、P1 100个，不能据P0这5个样本宣称冷读p99通过。另设独立冷启动阶段：同档硬件/数据，P0固定20轮访问全部5个预留owner，P1固定1轮访问全部100个预留owner；每轮先验证清除其应用结果及查询embedding缓存，固定请求与缓存重置manifest，累计至少100次冷首读并报告分位数及样本量。此阶段与正式吞吐分开计数，不称磁盘/数据库全冷启动，也不以100样本外推稳定的生产尾延迟。

故障阶段另行注入向量中断、导入1/3先到而2延迟5秒、worker暂停和ledger故障，按C用例验收并报告恢复时长；不得混入正常阶段后再把错误从分母剔除。full adapter的产品端到端吞吐另作集成报告，P1服务读写速率不等于完整产品请求速率。

### 7.3 费用与额度

每次报告分列新增source、query embedding、后台抽取、摘要、索引、Memory前台CPU/IO、主Agent注入token、主模型循环次数与产品工具。按每千条来源、每千次context和每千次完整记录请求给出费用，不采用旧文档的免费模型、单次调用数或价格。

发布前部署清单必须配置owner/tenant并发与token预算、后台积压阈值、每日调用额度、超限策略及使用的价目版本。缺少预算配置时真实抽取关闭，base ingest/search合同可独立验证；不能让worker无上限重试产生费用。真实实验额外申请的模型预算不能由本设计文档自动推定。

启用外部模型或批处理时，报告同时记录实际配置的请求/token速率额度及版本、限流与排队等待、有效处理速率和积压消化情况，区分算力不足、配额节流与预算暂停；不继承历史方案的厂商配额、免费或零成本假设。此为部署/实验归因，不新增业务API；结果未知的付费调用仍按03/06先核对，不用重试提高表面吞吐。

| 报告项 | 口径 |

| 建设与维护 | 分列首次构建、增量更新、复核、过期重算，以及前台读取、失效清理和存储；已有派生的历史建设成本单列，未知则标缺失，不将其当免费存量 |

## 8 运维 保留期与恢复验收

### 8.1 默认保留策略

| 数据 | V1默认 |
|---|---|
| 当前source与有效memory | 无自动到期；按显式TTL、用户擦除或授权策略处理，不因低检索频次删除 |
| 被更正旧revision正文 | 最长30天，只供受控审计，不进入普通召回；来源erase覆盖这些版本 |
| 幂等结果/operation详情 | 至少30天；稳定实体身份、revision去重与防复活标记不随缓存到期消失 |
| 默认正文调试日志 | 关闭；受控诊断启用时最长24小时，erase仍覆盖相关副本 |
| 无正文的审计元数据 | 30天；opaque ID/hash仍按个人数据管理，不声称匿名 |
| bundle正文缓存 | 最长5分钟且失效优先；仅hash/依赖审计按元数据保留期 |
| 本地擦除物理清理 | 正常依赖下applied后24小时内；立即停止可查询与物理回收分开 |
| 加密备份 | 最长30天滚动保留，擦除目标的残留备份最迟31天到期；过渡期恢复门禁禁止可见 |
| 防复活tombstone/擦除范围日志 | 至少覆盖所有可恢复备份和旧导入窗口；外部仍可能重放时保留最小opaque拒绝身份，不能随正文一起删除 |

普通30天元数据保留期不适用于尚未履行的full consumer清理义务。最小opaque bundle→来源lineage→consumer依赖、撤回范围和清理责任必须保留至可核验clear/reset/terminated证明成立，或继续作为最小控制记录保留；不能因审计到期、租约过期或宿主离线而从required_consumers分母移除。此例外不延长bundle正文或旧来源正文保留期。

允许租户收紧保留期；延长须版本化配置并重新检查用户承诺、费用和测试。字段“review_after”仅为复核提示，不等于自动删事实。

### 8.2 擦除与控制日志

生产擦除、授权撤回需要独立故障域的append-only控制/擦除日志，记录opaque目标、授权空间、代际、外部身份与操作状态，不含正文。先持久化意图，再提交本地失效事务；对外成功applied前需能核对两者。日志已记而数据库失败时保守阻止目标并保留pending，按operation恢复，不取消已接受的擦除意图。日志不可用时不得声称已完成可恢复的耐久擦除。

这是恢复旧备份时的安全依据，不是新的产品事件日志。不能只在同一份会回滚的数据库备份里留删除标记，然后宣称恢复不会复活。集成实现选择独立对象日志或等价耐久存储，release manifest记录其故障域与确认策略。

### 8.3 备份恢复与重建门禁

恢复实例默认不接普通读写。流程为：核验备份与schema → 载入最新擦除/控制日志和当前grant → 重放门禁与来源头 → 核对外部stream连续checkpoint → 对新旧索引代应用删除掩码 → 核对来源/记忆闭包与样例 → 启用只读验证 → 通过后开放。

无法证明擦除日志或授权状态是当前版本，继续封闭，不退回旧grant。不存在可恢复数据或链不完整时明确报告，不能以空库“恢复成功”替代。记录原始失败及重建代次；修正恢复流程不覆盖旧验收报告。

索引迁移双代期间，失效门禁同时作用于两代；回滚索引不回滚删除或策略。外部流缺口或冲突进入隔离队列，运维不能用“手动把水位改成最大值”解除。首次全量导入先固定权威快照与起始checkpoint，完成快照安装和增量接续核验后才能声明连续水位；不把下载完成当数据就绪。

开发验收要求在所声明档位同一数据上完成一次空白部署、进程重启、删前备份恢复、索引重建和流缺口修复。首发可在封闭读取下单代重建；启用在线双代迁移后再补切换/回滚验收。P0/P1各档恢复目标RPO≤5分钟、RTO≤60分钟，须分别实测；删除/授权状态不能接受这5分钟回退，必须通过独立控制日志恢复。不借目标数字宣称已经具备多地域灾备。

首发完成标志是：发布清单、适用合同测试、中文金标准与盲评、P0吞吐/冷读及费用、恢复/擦除演练、至少一个点滴full adapter报告齐备。MCP tool-only互操作、自动摘要或P1等扩展在声明启用时补各自报告。所有报告绑定同一设计版本及实际构建摘要；本轮仅提供验收合同，不生成虚构通过结果。

## 10 持久聊天补偿与首发适用验收

[06的H01–H15](06-history-ingestion-and-repair.md)按实际启用能力选取适用场景，不要求手工补采先建设自动巡检、重抽和全部通用连接器。发布manifest列明各H项的完整测试、必要变体或不适用理由；未开启的模式返回422 UNSUPPORTED_CAPABILITY，不用虚构通过代替。

| 交付能力 | 必测范围 | 可以后置什么 |
|---|---|---|
| A：首发在线可靠重送 | A11/A12及H01/H02/H05/H06/H07/H10/H11/H13/H14/H15中适用于在线写入、门禁、重送和付费恢复的变体；已有自动派生必须测H12 | 不要求history:run/cancel、MySQL分页、历史扫描、预览或自动巡检；H14只测已采用的任务取消/lease与付费恢复，不凭空新增history控制面 |
| B：受控手工MySQL补采/回填 | 共享安全项H01/H02/H05/H06/H07/H10/H11/H13/H14/H15，H03的immutable原文变化检测及H04分页/长跑turn；已有自动派生测H12；若启用已有source的两类repair，加测缺口定位、版本及重试 | 可关闭repair/reextract/自动巡检；可变原消息修订未支持时不测其正向能力，但必须验证旧页及变化阻断 |

H12须覆盖显式remember先于自动派生、晚于自动派生及二者并发，验证同一受保护slot不会因换memory_id/pipeline另起重复自动条目；revise换source/schema/subject而新范围已有另一当前头时返回MEMORY_SLOT_CONFLICT，不自动抢占。H13验证聊天删除后正式回执晚到仍正常applied，关联保留blocked，既不复活原聊天也不卡住业务流。H14对取消准入两侧、旧lease、owned子job与复用live job、未知embedding分别注入故障：取消回执不冒充无在飞，未知调用不自动重发，顶层cancelled仍披露未决费用phase。H15验证首次create竞争后只读复用canonical来源，不使用latest CAS自动覆盖；真正更正必须有明确修订意图及当前性证明。

启用[06§7.3定向派生复核](06-history-ingestion-and-repair.md#73-定向派生复核c扩展)时，C2另选以下固定变体，沿用既有编号而不另增主矩阵：H08/H12验证来源未变的自动抽取错误及复核期间的人工修订；H09验证正常empty、复核到期或访问频繁均不能直接判错或改写事实；H06/H07验证运行期间撤权/删除，H10/H14验证取消、旧lease及付费结果unknown。复核产生新版本后，旧bundle、工具历史和摘要/交付副本的失效沿C06/C20/C22及A08/A10适用变体核对。未启用定向复核时不运行该pipeline；只启用B时不接受自动复核或reextract，按既有能力门禁拒绝，其他重抽pipeline是否可用仍按各自声明判断。不把A的可靠重试、明确更正或失效后置。

history:run/cancel和GET operation仅在启用history控制API时按02/06合同测试。扫描complete、source_applied、派生/index complete分别报告；H02的不重复语义为来源/发布去重及未知调用不自动重发，不承诺所有安全重试都免费。

补偿效果分别标注source存在性、派生覆盖及最终交互收益；回填前后的比较使用相同reader、时间前缀、授权和预算，不能引入未来更正泄漏金标准。统计扫描重复率、漏采率、误抽assistant事实、重抽覆盖显式修订、删除复活、费用未知重调；身份、授权、角色/权威和删除复活仍为硬门禁。

原有P0报告不自动证明后台并行容量。启用巡检/重抽后冻结后台速率、并发、调用额度及资源配额，重跑与前台竞争测试：前台仍满足所声明P0目标，后台超额须节流/续扫并披露积压，不侵占前台deadline或无限追加费用。报告原source可发现→接受、接受→派生发布、独立删除控制→本地gate的各段滞后及待核对turn数，不把60秒调度周期当全历史完成SLO。
