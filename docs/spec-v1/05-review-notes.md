# V1 整体审查与修订记录

日期：2026年10月27日。对应设计版本：V1.1。本记录说明本次静态设计审查的结论；开发合同仍由[整体入口](README.md)及00–04共同组成，不引入另一份接口定义。

服务边界方向合理：独立记忆负责可追溯证据、相关性召回、偏好及使用限制；产品后端负责正式记录与精确统计；Agent负责理解、调用及回执恢复。原稿的主要问题是几条正文和更新通路未进入同一失效闭环，以及把扩展能力混入首发出口。以下问题已直接修入相应分册。

## 1 必须修复的闭环问题

| 问题 | 已采用的最小修订 | 文档与验收 |
|---|---|---|
| 只有prepare包被追踪，search/get/facts工具正文可留在旧history | 所有full正文读取共用两类bundle、登记consumer及精确依赖；复用validate/changes/ack/reset，不增第二套机制 | 01§9、02§2.6/§12、03§5；C20 |
| 正式条目更正了，原用户话语仍可重新抽出旧数值 | 可信事件携带input_evidence_refs；更正同事务限制旧原断言。缺精确关联时保守隔离同group/entity/domain，晚到原输入和旧worker也受限 | 01§4.4、02§3；W4、C18 |
| sync新镜像可被积压旧Outbox覆盖，opaque外部版本无法排序 | 外部条目只经唯一注册ordered_import流发布，直达只加速同一事件，不能绕序换头 | 01§7.2、02§3、03§3；C19 |
| 范围布尔fence可能永久不关，或被另一并发动作误清 | 绑定稳定action_id；未发出或权威证明无提交可关闭，unknown保留，committed只按对应Memory屏障关闭 | 03§3.3；A09 |
| lease/尚未收到change被用来替代在线校验 | 首发保留依赖历史的模型step、工具及交付前在线validate；不以通知未到证明没有更改 | 02§12、03§2/§5；C14–C16 |

## 2 降低首发复杂度

| 原要求 | V1.1处理 |
|---|---|
| Memory保存candidate拆分、拒绝及提交映射状态 | 移回Agent/RecordService journal；Memory只保留来源与外部条目的必要证据关联 |
| 确认picker保存前串行等记忆检索 | 可信适配器可持久deterministic_no_history，直接正式提交；原输入/回执仍可靠补镜像 |
| MCP、多Agent包装、自动摘要、精细片段授权、双代迁移一起首发 | 首发HTTP核心＋点滴full适配；其余独立扩展验收。没有可靠片段授权时按整源授权拒返，不猜测拆分 |
| 默认按630万来源和50读RPS作为开发出口 | 首发P0：12万来源、5读/2写RPS及真实依赖；P1大容量另测，不能外推能力 |
| 必须部署第三方框架作为上线前置对照 | 首发保留无记忆/近期/混合检索基线，框架对照作为选型扩展 |

保留来源版本、CAS/幂等、连续屏障、证据依赖、擦除门禁、独立控制日志与full清理。这些直接防止重复记录、旧事实回退、撤权后读取和备份恢复复活，不以删掉保证来降低实现量。独立控制日志可采用等价耐久存储，不要求再建设通用事件平台或多地域系统。
