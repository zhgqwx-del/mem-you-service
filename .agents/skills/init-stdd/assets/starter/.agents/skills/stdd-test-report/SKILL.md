# 生成验收记录

1. 读变更范围、确认后的规格、测试计划和已有证据。按受影响的 AC 选定定向用例、项目需要的回归与手工检查。定位当前受测范围和测试入口。
2. 按仓库约定运行实际脚本，记录命令、退出状态、环境、数据、受测 SHA 或工作区状态。分别标明行为断言失败、环境阻塞与未执行。能独立执行的检查照常记录。
3. 手工验收按场景给出最小步骤、数据和预期。已经执行的由实际观察填结果，其他场景标为待验证。使用 `docs/stdd/templates/verification.md` 汇总自动与手工证据，引用仍相关的旧记录并写清对应版本。
4. 回报通过、失败、阻塞和待验证的场景及复跑入口。修复问题时沿对应的实现任务处理。
