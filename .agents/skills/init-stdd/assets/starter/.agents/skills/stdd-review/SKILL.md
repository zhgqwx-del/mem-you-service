# 审查变更

1. 根据用户请求、PR 目标或仓库约定确定范围。审查已提交分支时，用 `python3 -B scripts/git_range.py --merge-base <目标引用> <候选引用>` 定位增量，再读有影响的 diff。审查工作区改动时查看已暂存和未暂存的相关差异。
2. 先扫改动范围和依赖，再读取目标分支的评审规则（如有）、已确认的规格和实施方案。沿变更查调用方、数据状态和副作用，核对边界、失败、兼容、并发或权限等与本次相关的风险。关注是否混入无关改动，以及删改测试断言和 CI 的实际理由。
3. 将 `REQ-*`、`AC-*`、测试和证据关联起来，检查受测提交是否对应当前候选。核对变更所引讨论和 ADR 的状态、影响及可达性。缺少证据时，按任务范围复跑关键用例或列出待验证项。
4. 按影响给出发现，附文件与行号、触发条件、受影响场景和可观察后果。区分已确认缺陷与仍需复核的问题。Git 比较只读取现有引用，维护分支的操作沿用项目流程。
