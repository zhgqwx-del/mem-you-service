# 讨论与架构决策

每项变更从 `changes/<id>/change.md` 进入。将影响本次范围、方案或验收的资料列在「关联讨论与 ADR」下，链接到实际文件或工单。正文只保留本次影响和未决事项，讨论过程与长期约定各自维护。

## 何时单独记录

| 情况 | 记录位置 |
| --- | --- |
| 只影响本次变更，能在一次评审中决定的问题 | 写入本次 `change.md`，实现细节放在 `tasks.md` 或 `design.md` |
| 跨角色、团队或变更，需要多轮评审、比较备选方案，或需要持续跟踪证据 | 优先复用已有讨论。需要单独文件时，沿用仓库讨论目录，默认放 `docs/discussions/<topic>.md`。用[讨论模板](templates/discussion.md)记录问题、选项、结论和关联变更 |
| 会约束后续变更的架构、契约、数据或运维决策 | 用 [ADR 模板](templates/adr.md)记录决策理由、后果和复查条件。待确认方案使用「提议」状态，确认后标为已采纳 |

一次跨团队讨论可以先比较多个方案，再形成 ADR。只有本次有效的选择可在讨论中链接回变更及最终方案。后续变更直接引用仍生效的 ADR。

## 确定 ADR 的目录

1. 先找当前项目或模块的 `AGENTS.md`、工程约定、ADR 索引和已有引用。有明确位置时沿用该目录、编号和状态格式。
2. 如果只有 `docs/adr/` 或只有 `docs/decisions/`，复用现有目录。两者都有时，根据索引、已生效的相关 ADR 或模块约定选择对应位置。资料仍有歧义时，列出候选路径和相关记录，请负责人确定新文件位置，其他工作可以继续。
3. 两处都没有且出现首个需要长期保留的决策时，再创建 `docs/adr/`。优先查找可引用的既有 ADR。需要写新 ADR 时用未占用的编号。替换旧决策时按约定记录被替换和替代的 ADR。

## 链接与归档

- 在变更的「关联讨论与 ADR」中链接讨论和 ADR 的真实路径，并简述它们影响了哪条规则或方案。讨论和 ADR 可链接回相关变更。已有决策覆盖本次需求时，可直接链接既有 ADR。
- 从 `changes/<id>/` 归档到 `changes/archive/<id>/` 后，检查变更目录内所有指向外部文件的相对链接，并同步修正讨论、ADR 或索引指回旧位置的链接。保留变更和 ADR 的编号，核对归档后的目标可打开。
- 例如，从在途变更链接到 `docs/decisions/ADR-0007-message-id.md` 时使用 `../../docs/decisions/ADR-0007-message-id.md`。归档后使用 `../../../docs/decisions/ADR-0007-message-id.md`。
