# 开发收尾与交接

1. 核对当前候选和合入目标，读取仓库约定及 `docs/stdd/git-workflow.md`（如有）。准备提交时，只将已经约定或明确要求的 Git 同步步骤纳入流程。需要 rebase 时先核对基线、工作区和分支共享状态。记录冲突与当前状态，按已确认的处理范围解决。squash 可由 PR 合入步骤完成，本地整理提交按项目约定及授权执行。
2. 同步实际交付的规范、契约和任务。按 `docs/stdd/decisions-and-discussions.md`（如有）记录讨论结论，长期架构决策沿用项目指定的 ADR 目录或已有 `docs/adr/`、`docs/decisions/`。在 `change.md` 关联相关讨论与 ADR，通用做法回写工程文档。合入前按仓库流程归档，校正变更向外的相对链接和讨论、ADR 或索引指回变更的链接，并验证目标可打开。记录仍待接手的事项与复跑方式。
3. 运行项目适用的提交前检查，包括定向验收、构建、lint 和回归。在 rebase、整理提交或其他内容变化之后，核对候选与已验证的内容，复跑受影响检查。将实际命令、退出状态、失败和待验证场景记入 `verification.md`。检查失败时用实际结果标记当前交付状态。
4. 使用 PR 模板准备范围、方案确认、受测证据、影响、待办和撤回方式。交接时保留候选 SHA 或本地状态、下一步和复跑入口。提交、推送和发布依据任务授权执行。
