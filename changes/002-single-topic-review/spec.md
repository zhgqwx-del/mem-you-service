# 单主题个人经验与规律回顾规范草案

## 范围

用户从当前 Agent 会话明确发起一次个人回顾。范围为本人、一个已注册主题、一个过去的观察窗口。试点注册「出门准备与漏带物品」，领域为 `personal.life`。数据限已摄取且允许此用途的来源。结果是本次受控回顾的回复及证据，依照宿主交付与清理协议管理。长期洞察、自动触发及跨主题合并留待独立评审。

## 需求

### REQ-REVIEW-001

可信宿主从真实用户请求及会话状态确定主动意图、主体、主题和用途。试点默认取可信用户时区最近 14 个已结束的本地自然日，自定义范围为 1 至 28 个连续且已结束的本地自然日。对明确的起止日期，以当地起日午夜及止日次日午夜形成半开区间，按自然日计算，跨夏令时按各边界的实际偏移处理。主体、主题、可信时区或边界不明，以及请求跨主题、含当日、倒置或超范围时，先请用户选定有效范围或明确当前能力边界。历史稀疏时可建议扩大范围，用户另行选择后再发起回顾。纯回顾可以留宿主操作痕迹，产品记录和偏好写入须来自各自独立、合法的用户意图。

### REQ-REVIEW-002

按固定的已应用前缀和发生窗口，从当前获授权且可用的来源有界取证。以实际出门日期归窗，授权内且能证明与该次出门对应的前夜证据可随事件取证。窗口尾日后的迟记只要在前缀内仍可纳入。预筛条件须能证明保留合格事件，无法证明时须明示范围缺口。按可信事件身份关联原话、转写、同一事件的正式镜像及重送。来源组只做关联，真实独立事件分别保留。无法验证独立性的描述可带出处回顾，不能用于重复计数。现轮陈述、助手转述与旧归纳只按各自现行用途使用。

枚举覆盖、候选判读完成度、真实生活记录覆盖分别说明。候选范围须有可核对的尾页或截断状态，候选证据逐条有判读结果或未能判读的理由。影响某项结论的候选未取齐、未能归窗、未决身份或判读失败时，该项按部分覆盖处理。授权或当前性无法核验的范围不得出正文。用于选样、计数、反例及结论适用限制的来源版本纳入依赖，即使未在答复里展示。有界覆盖状态只由可授权范围和服务状态产生，不能借诊断泄漏隐藏材料。

可信宿主按[内部取证协议 v1](design.md#内部取证协议-v1)先准备冻结范围，再按服务签发的游标取证。每个阶段使用同一 operation 的[试点资源预算](#试点资源预算)。完全枚举须由服务证明遍历到尾。材料因条数、字节、时间或判读预算而未取齐时，只能依据已验证个案安全降级。

### REQ-REVIEW-003

在输出中区分用户自述的单次经历、重复行为或场景选择、结果比较。重复观察至少要有不同出门日的两次可信独立事件，且在可比情境中呈现同一可观察的做法。形成重复选择观察时，各次实际可选方案须有证据。门槛仅用于试点的重复观察，单次明确自述仍可回顾。用户亲述某做法有帮助时注明为当次自述。若同一事件的结果互相矛盾，采用明确指向目标的更正或有效权威修订。仍冲突时保留可核对的双方证据，事件计一次，结果退出已知结果分母，与缺结果分列。

程序从已核验的事件生成分组、计数、必要反例和覆盖限制。最终答复承接这些项目及精确引用。发现结论与事件、计数、必要反例或引用不符，或者该结论只完成部分取证时，回退到可核验的具体经历与缺口。已知结果合计只使用明确且未冲突的结果，比例若使用须注明分母、缺失和记录覆盖。整个期间的正式次数、频率或趋势由产品权威工具提供。试点不据记录样本断言因果、持久偏好或总体生活规律。

### REQ-REVIEW-004

普通网络重试保留 operation、准备版本、请求哈希和冻结前缀，重新验权并检查依赖。同一键变更范围按幂等冲突处理。失效或过期的旧准备仅可返回安全状态。原回合仍有授权、需要继续且执行时限和额度均有剩余时，允许一次新准备版本，以新键保留归一化的主题与窗口并冻结新的已应用前缀。自然到期的旧使用包已超出一次回顾的执行时间，用户可另发请求获得新 operation 和前缀。未知模型调用先按原调用身份核对。

逐页取证、入模、依赖工具、交付及重放均复核已知产品待定动作的阻断状态（pending fence）和适用读取屏障。某动作结果未知或对应的更正尚未应用时，该动作影响的内容继续阻断。来源失效或依赖无法核验时，整份受影响的旧回顾退出使用，当前证据须重新取证。宿主在发送准入口执行授权与失效门禁，从宿主已立 fence 或检测到失效起停止待发正文，并按现行协议隔离历史、缓存及摘要后确认清理。已经交付到不可控位置的内容按现行边界处理。关闭功能后仍处理已产生的副本和依赖。

用户报告上次总结有误时，可以澄清或沿既有更正流程收下可信依据。新回顾使用已应用的依据，回顾入口自身不改产品台账。

### REQ-REVIEW-005

只允许登记的 full_lifecycle 宿主发起试点读取。宿主从可信上下文绑定 `answer_history`、目标主体和使用者，程序核验 grant、范围、策略和有效版本。试点归纳排除 `direct_reference_only` 及 `historical_only` 证据，普通上下文和旧摘要中的受限正文同样不得进入归纳或计数。明确请求旧原话时由原有直接取证路径处理。`suppress_proactive` 在用户明确回顾时仍按现行可见使用策略执行。结果、引用和缺口均不得泄漏其他主体、未授权域或隐藏来源的存在。反复的当轮要求或场景选择只有当次的观察效力。可信用户另行明确长期偏好时，沿已注册的显式偏好路径处理。

### REQ-REVIEW-006

按 owner 保持相同历史前缀、主模型、授权和总模型预算上限，成对比较普通历史召回与单主题回顾。开发集比较既定 14 日默认和用户选择 28 日时的可回答率、缺口和成本。封存评测使用固定窗口策略。试点设计采用全套确定性场景及 04 适用门槛、足够证据正确归纳率至少 90%、不足证据正确降级率至少 95%、按 owner 等权效用评分至少 0.55 且双侧 95% 区间下界大于 0.50。样本量及分层配额、关键分层门槛、发布时延和成本线按开发集和产品预算在封存前冻结。各门槛分别判定，样本或预算不足、阈值尚未冻结或效果证据不足时，能力保持未启用。评测数据、模型及策略版本和实际成本须可追踪。 [同预算效果对照](test-plan.md#同预算效果对照)

## 验收场景

### AC-REVIEW-001

关联 [REQ-REVIEW-001](#req-review-001)。

- **Given** 可信宿主收到本人明确回顾试点主题的输入，另备普通记录、未知时区、空或倒置范围、含当日、超窗、跨夏令时和多主题请求。
- **When** 各样本通过相同宿主入口执行。
- **Then** 合法请求仅进入一次指定范围的回顾，范围歧义需要澄清，稀疏窗口也不自动扩展。普通记录继续原路径。操作记录可确认回顾的语义范围及产品记录和偏好均未被回顾动作改写。

### AC-REVIEW-002

关联 [REQ-REVIEW-002](#req-review-002)、[REQ-REVIEW-005](#req-review-005)。

- **Given** 本人和其他主体有同文事件，本人单次事件有原话、同事件镜像和重送，另有不同日期的独立事件、混合域输入及前缀外晚到记录。
- **When** 宿主固定一次观察前缀，分页取证并重试同一请求。
- **Then** 每个可证明独立的有效事件计一次，晚记的窗口内事件及可证明关联的前夜证据可纳入。当前请求、前缀外、不可用来源及旧回复退出输入集。输出、引用、计数、页面和诊断均只反映本次获授权范围。同题授予范围不变，仅改变隐藏记录时，可见覆盖结论和诊断也不变。

### AC-REVIEW-003

关联 [REQ-REVIEW-003](#req-review-003)。

- **Given** 同一做法至少两次独立使用记录，样本包含明确受益自述、明确失败和结果未知。另备同一事件两份有效材料冲突、判读漏反例与成文省略反例的变体。
- **When** 用户问「哪些准备办法曾经有帮助」。
- **Then** 回答列出做法、已记录的好坏结果及未知项，每项可定位到对应证据。冲突事件只计一次，结果不进入已知分母。未完成的判读及有遗漏、错误或越界断言的成文按阶段记录，受影响结论不得交付。单次经验单独标注出处。

### AC-REVIEW-004

关联 [REQ-REVIEW-002](#req-review-002)、[REQ-REVIEW-003](#req-review-003)。

- **Given** 两个不同日期的独立事件记录同一场景及同一选择，另有意图、重复描述和普通临时要求。
- **When** 用户问「我通常怎么准备」。
- **Then** 回答给出记录范围内的选择观察，明示时间和场景。意图、临时要求及重复描述不能制造独立行为或长期偏好。完整趋势或全期比例超出已知分母时应缩小说法。

### AC-REVIEW-005

关联 [REQ-REVIEW-002](#req-review-002)、[REQ-REVIEW-003](#req-review-003)。

- **Given** 可用历史为空、只有一次经历、发生日期未知、枚举或判读因预算未完成，或当前性读屏障失败，分别运行。
- **When** 发起同一合法回顾。
- **Then** 正常无适用证据、可回顾个案、已知部分覆盖及无法安全读取分别给出对应结果。缺少支持时拒绝归纳，当前性未获证明时不展示该范围的正文。

### AC-REVIEW-006

关联 [REQ-REVIEW-004](#req-review-004)。

- **Given** 首次回顾冻结后接收一条落在相同发生窗口的新反例。分别设置首次已完成、第一次准备在执行期限内失效、原执行期限用尽三个状态。
- **When** 重试原请求、尝试同键改范围，在仍需继续的原回合重新准备或回看已到期答复，再由用户另发同范围回顾。
- **Then** 普通重试只复用仍有效的固定结果，同键改范围冲突。执行期限内的合格新准备保留主题与窗口，冻结新前缀且继续扣用原预算。超出执行期限禁止重取证。到期回看只显示状态。新用户请求使用独立 operation，纳入新反例，原回答不作为新证据。

### AC-REVIEW-007

关联 [REQ-REVIEW-002](#req-review-002)、[REQ-REVIEW-004](#req-review-004)、[REQ-REVIEW-005](#req-review-005)。

- **Given** 回顾使用多页证据，并有待交付正文、已受控保留的答复或摘要。注入 Memory 未追上的产品更正、已用证据失效、整 grant 撤销、消费断档。分别覆盖取证、入模、最后在线校验之后到实际发送前、发送中及重放。
- **When** 执行上述步骤、重试并处理消费者变更。
- **Then** 已知阻断和失效的依赖不能进入后续页、模型、发送队列或可控重放。整份受影响候选退出使用，即使被改证据仅影响未在答复中明示的计数或结论。新准备只使用通过核验的证据，清理前不得 ACK，断档按协议 reset。

### AC-REVIEW-008

关联 [REQ-REVIEW-004](#req-review-004)、[REQ-REVIEW-005](#req-review-005)。

- **Given** 已有适用的显式长期偏好，来源另有多次临时请求、用途受限内容及模型伪造的历史用途。
- **When** 回顾并另以真实用户输入明确更改长期偏好。
- **Then** 回顾不会升级推断或写入偏好，受限证据不会参与归纳或泄漏。明确的长期变更由原可信接口产生新记忆回执及旧依赖失效。

### AC-REVIEW-009

关联 [REQ-REVIEW-003](#req-review-003)、[REQ-REVIEW-006](#req-review-006)。

- **Given** 固定测试前缀、中文真实任务形态的隔离样本及正反例标注，两组固定相同的授权、主模型和预算上限。
- **When** 对照普通相关历史召回与单主题回顾。
- **Then** 分别报告引用、正确弃答、误归纳和任务收益，样本和实际消耗可复查。适用安全硬门禁及评审确认的效果门槛通过后，交付报告方可声明该能力就绪。

## 试点资源预算

下表为 002 的初始试点上限，按 `tenant + owner + operation` 累计。每次合法的新回顾分配一份预算。实现和离线验收以这一版口径为准，试点数据用于验证这些上限能否覆盖目标场景。

| 资源 | 初始试点上限与计量 |
| --- | --- |
| 枚举 | 全操作最多检查 512 条获授权的候选元数据。服务先执行授权范围谓词，再计逻辑候选。达到上限但无法证明遍历结束时标记部分覆盖 |
| 正文 | 每页最多 12 个精确来源版本、16 KiB 序列化投影。整个操作最多 4 个已登记的逻辑页、48 个来源版本、64 KiB 投影。页内按精确版本去重，跨页复用只传引用。新准备重新物化的证据照实际扣额度。投影以实际 UTF-8 字节计，含引文、来源版本、日期及参与归纳的字段元数据。终页或空页若登记使用包，也占一页 |
| 执行时间 | 从 operation 首次获准执行起，宿主按单调时钟计时。内部调用至多 2 秒，且不超过阶段剩余时限。满 10 秒停止发起新的取证或模型调用，保留最后 2 秒用于复核、呈现和交付。达到 12 秒时只可返回安全状态。跨进程按可信剩余预算限制本地执行，重启无法证明余量时须拒用 |
| 准备与重试 | 每 operation 最多 2 个准备版本，含一次合格重准备。每个逻辑调用最多 2 次传输尝试，含一次重试。已登记页的原样重放不重复扣逻辑页、来源和投影预算，受原调用次数、执行期限和在线核验约束，包期限不续 |
| 模型 | 本次回顾最多 2 次模型调用尝试，累计最多 8,192 输入 tokens、2,048 输出 tokens。包括为本次回顾执行的意图判读、候选提取和回答调用及合法重试，系统提示和证据均计。发出前记录调用身份和请求哈希，预留可核验的输入与最大输出额度。额度无法核定或已耗尽时停止新付费调用 |
| 并发 | 单个 tenant 内，每个 owner 跨 grant、会话及 Host 同时至多一个回顾 operation 在执行。普通重试接续原操作，另一独立请求给安全的忙状态。已发调用结果未知时单独保留其使用和费用预留，直到沿原身份核对 |

准备版本变化与失败重试不补回已经消耗的额度。模型用量或收费未知时继续保留预留，禁止更换调用身份盲重发。迟到的页和模型结果仍登记实际消耗与清理责任，不进入新正文。执行期限约束服务与宿主的准入及交付，客户端传输耗时和第三方推理取消状态另行记录。A 既有端点限额与 04 的标准预算用例各自适用。已完成回顾在原使用包有效期内的受控回看只复核原依赖，走回看路径时不发起新取证或推理。

预算先碰线而授权、读屏障、全部实际依赖仍可核验时，可在保留的交付时间内呈现已核验个案及范围缺口。预算本身不足以完成安全校验、当前性失败或已过截止，则无历史正文。监测取证与判读时延、用量、截断、过载和费用未知。发布用的 P95 时延、实付成本、全试点并发及开销上限在取得授权开发样本和部署计价信息后登记并冻结。资源硬上限由本文定义，后续调整须记录版本和依据。
