# 单主题个人经验与规律回顾技术设计

## 目标与约束

以已摄取的个人记录回答用户主动发起的一次历史回顾。首个主题为「出门准备与漏带物品」，只处理已明确为本人的授权 `personal.life` 材料。观察只用于本次回答。正式记录、精确统计、来源镜像、偏好写入及其失效继续由现有合同约束。 [变更入口](change.md) · [草案规格](spec.md) · [C 扩展范围](../../docs/spec-v1/README.md#33-c后置能力)

## 请求绑定与固定前缀

关联 `REQ-REVIEW-001`、`REQ-REVIEW-002`、`REQ-REVIEW-005`，覆盖 `AC-REVIEW-001`、`AC-REVIEW-002`、`AC-REVIEW-008`。

1. 可信宿主核对已接收的用户 turn、明确的历史回顾意图和主体，绑定 operation、session、turn、主题及现行授权。用途沿用 `answer_history`，模型只能建议主题归类，程序以注册主题和真实用户请求判定是否启动。当前输入是请求条件，其来源与同组镜像不计入历史样本。范围不明时请用户缩小到一个主题或明确主体。 [02 §2.6](../../docs/spec-v1/02-api-contract.md#26-所有记忆正文读取的用途与失效追踪) · [03 §2.3](../../docs/spec-v1/03-agent-sequences-and-recovery.md#23-当前输入与历史证据分离)
2. 以可信请求时刻和用户 IANA 时区解析本地日期。按已确认的设计，默认取请求日期之前 14 个已结束的本地自然日，自定义范围为 1 至 28 日。两端分别换算本地午夜，以半开区间归窗，夏令时跨日按自然日计算。超范围或时区不明时请用户选定范围或时区。记录稀少时仍按选定窗口回顾，扩大范围由用户再次发起。迟记事件按实际出门日归窗，材料须在本次准备时已应用。发生日期未知或可能跨界的记录记为缺口，可另作明确限定的个案，退出窗口计数。 [01 §2.3](../../docs/spec-v1/01-data-model.md#23-四类时间分开)
3. 准备版本在同一 operation 和 turn 下固定请求哈希、规范化主题及窗口、截止时已应用的来源前缀、读屏障及授权控制代际。分页、分步处理和普通重试沿用该版本，可采用物化的有界精确来源引用集或等价的固定快照与可验证游标。后续普通新增记录留给新的准备或回顾请求。每页还需验证当前精确版本、grant、失效条件及宿主 pending fence。若已入选证据的版本、授权或相关门禁改变，旧准备的页面、事件和候选一起退出，取得合格的新准备版本后重新枚举。 [02 §2.4–2.6](../../docs/spec-v1/02-api-contract.md#24-写回执与新鲜度)

## 取证与事件归并

关联 `REQ-REVIEW-002`、`REQ-REVIEW-005`，覆盖 `AC-REVIEW-002`、`AC-REVIEW-005`、`AC-REVIEW-008`。

| 环节 | 拟议处理 |
| --- | --- |
| 范围枚举 | 在 MemoryService 的已摄取来源与可回查的投影中，按 owner、本人主体、主题允许领域、授权及已应用前缀限界枚举。可证不会漏掉合格事件及相关证据时，才按来源元数据裁剪范围。按接收时间、单个来源日期、词法或向量命中裁剪，若覆盖无法证明，按部分覆盖处理。窗口首日前夜的证据可通过可信关联精确补取，仍须在获授权的范围内。一条来源中的多次出门逐事件归窗。枚举完成只表示规定的已摄取候选范围已查完。 |
| 适用材料 | 使用可信用户原话、允许投影和确实关联的有效正式条目。`historical_only`、`direct_reference_only`、不适用于该用途及不可安全投影的内容不进入归纳输入。用户另外要求查原话时，沿原取证合同处理。模型回复、历史归纳和压缩摘要不能成为新的用户事实，助手转述原话也不能增加事件样本。 |
| 覆盖与当前性 | 将枚举是否读齐、候选是否判读完成、出门日期或结果是否已知分别记录。对可见材料逐项记录判读适用、不适用、无法判明或处理失败，保留精确引用与原因。若有待判材料、无法证明的遗漏范围或资源限制，在授权、读屏障及依赖当前性均通过且仍在截止时间内时，只回顾已核验个案，并说明已知覆盖缺口。屏障或当前性无法证明时，受影响范围无正文。空结果和缺口只依据可见集合及服务覆盖，隐藏材料增减不改变可见状态、计数和诊断。 |
| 事件身份 | 优先使用可信正式事件身份及精确的原输入关联。对聊天使用原生消息身份消除重送，同一事件经原话、回执或更正出现多份时，仅形成该事件的不同来源引用。`source_group_id` 只关联同次输入与后续材料，同组可以有多次独立事件。若一条消息明确提到不同日期或独立出门事件，可用可核验的时间、明示指代和出处片段区分。没有可信关联时保留原陈述与歧义，不以文本相似度或可疑重复当独立支持。 |
| 前后结果配对 | 每次出门单独核对情境、准备做法、实际发生的结果和相应时间。归窗和重复观察的本地日期均取出门当日。来自多条记录的前夜准备与次日结果，只有在用户明确关联或可信身份可证明对应时才配对。计划、愿望、否定和他人经历保留原语气。 |
| 单事件冲突 | 同一次出门的相反结果先按明确指向该事件的用户更正或权威来源当前修订处理。仍冲突时保留双方的获授权引用，事件计一次，结果单列为冲突，退出已知结果分母。未记结果也退出分母，单列为未知。 [01 §5.3](../../docs/spec-v1/01-data-model.md#53-关系冲突和语义去重) |

`context:prepare` 和 `evidence:batchGet` 分别用于相关性召回和精确取证。下述内部协议负责枚举，首版只读取 MemoryService 已摄取的来源。 [02 §7–9](../../docs/spec-v1/02-api-contract.md#7-证据搜索post-v1search) · [01 §4.1、§4.4](../../docs/spec-v1/01-data-model.md#41-source_group同一次输入及其后续解释) · [06 §4](../../docs/spec-v1/06-history-ingestion-and-repair.md#4-什么可以抽取)

Host 在模型或工具接收前隔离同 turn 的常规 `context:prepare`、直接引文、旧回复和摘要。任何带 `direct_reference_only`、`historical_only` 或无可证依赖的正文都不能进入本回顾的模型提示、工具或计数。混合包整体留在归纳流程之外，必要时服务重新准备一份可核验的上下文，宿主按合同原样交付。当前交互所需的必要约束由受控路径核验和交付，作为约束使用。 [02 §2.6](../../docs/spec-v1/02-api-contract.md#26-所有记忆正文读取的用途与失效追踪) · [03 §2.2](../../docs/spec-v1/03-agent-sequences-and-recovery.md#22-当前-agent-service-的落点与新增工作)

## 内部取证协议 v1

由经过认证且具有 `evidence.read` 和使用包复核权限 `context.read` 的 full_lifecycle 宿主调用 MemoryService 内部逻辑操作。服务从可信凭证和已登记 consumer/会话解析租户、owner、grant 和本人主体。可信宿主依据已接收的用户请求绑定受限的 `answer_history` 用途和注册主题 `outing_preparation`，并复核该 operation 的 pending fence。内部操作语义在本草案中定义，进程内调用或私有传输、路由及存储查询由接入时决定。公共合同继续用于现有工具与端点，模型和 MCP 工具不能调用该枚举协议。关联 `REQ-REVIEW-001`、`REQ-REVIEW-002`、`REQ-REVIEW-004`、`REQ-REVIEW-005`，用 `AC-REVIEW-002`、`AC-REVIEW-005` 至 `AC-REVIEW-008` 验收。

| 逻辑操作 | 入参 | 成功回执 |
| --- | --- | --- |
| `reviewEvidence.prepare` | 可信宿主传 `operation_id`、`consumer_context`、`preparation_revision`、幂等键、主题、规范化本地窗口与 IANA 时区、当前输入的排除身份及适用的 `read_after`。窗口使用持久 operation 的可信请求时刻验证。服务计算规范请求哈希，绑定认证主体、操作、准备版本、用途、窗口、排除条件、屏障、主题策略和服务端预算版本。 | 返回不透明的 `scan_id`、`first_cursor`、`request_hash`、`snapshot_at`、回显的窗口及扫描截止时间。服务内部冻结截止时已应用的前缀和稳定排序键。回执没有来源正文、命中数或覆盖断言。即使没有候选，也须读取首个空尾页来验证覆盖。 |
| `reviewEvidence.readPage` | 传 `operation_id`、`consumer_context`、`preparation_revision`、`scan_id` 和游标。服务按准备回执重建原查询，继续执行原 `read_after` 和当前有效性校验。 | 返回固定 `scan_id`、页号、已授权投影项、`scan_status`、`coverage`、`next_cursor` 与现有 `usage_bundle`。每项有精确 `source_id`、`source_version`、授权片段或结构化投影、可用的时间精度和可信关联线索。各项保持原始语义和来源权威，供下步逐项判读。 |

1. 准备先过当前授权、用途、待定写阻断和 `read_after`，再固定实际已应用前缀。`read_after` 沿用现行上限，最多 8 个外部屏障、32 个所需来源，实际取证依赖分别登记到对应页面的 `read_result`。按来源身份及精确版本的稳定顺序枚举，保留可能合格的材料，包括已获授权的前夜关联、迟记和多事件来源。无法凭元数据安全排除的授权项保留在候选范围内。需要的授权链路无法读齐时，记录覆盖缺口。游标由服务签发，绑定该 `scan_id`、授权投影、准备哈希、固定前缀及页位置。单个来源版本在该准备中最多占一个投影项，可带多个授权片段。普通重试沿用原前缀。 [02 §2.4](../../docs/spec-v1/02-api-contract.md#24-写回执与新鲜度)
2. 首个游标只能由 `prepare` 取得，次页游标只在前一页成功登记后签发。每页冻结正文与状态、登记 `read_result` 后再响应。同一有效扫描和游标的普通重试或并发读取复用该页和原使用包，重验当前授权及依赖，不延长原包 TTL、不重复推进或扣减取证额度。合法调用者传入与扫描不匹配的游标按冲突处理。跨调用者和不存在的扫描均按现有不可见语义处理。一个准备的页集不得与另一准备混合。
3. `scan_status` 为 `in_progress`、`complete` 或 `partial`。只有 `in_progress` 带 `next_cursor`。`coverage` 回显 `snapshot_at`、固定的发生窗口、是否已核验尾部及允许披露的缺口原因。`complete` 表示在固定授权范围内证明已到候选尾部，所需投影与可证关联均读齐。`partial` 表示因限额、裁剪或可说明的已授权覆盖缺口而终止枚举。已登记的成功空尾页也以同一类 `read_result` 绑定范围、前缀、屏障及尾部依据，允许引用集合为空。只有完整枚举加上判读完成且无符合证据，才可回答「这段已摄取记录中没有适用证据」。部分、失效、超时和无法核验分别处置。 [01 §9.2](../../docs/spec-v1/01-data-model.md#92-统一使用包-context_bundle-与消费依赖)
4. 候选步进、页、投影项、响应字节和请求耗时受[试点资源预算](spec.md#试点资源预算)约束。准备、分页和关联补取共用 operation 额度。触及资源上限而未证实尾部时，能在期限内登记安全结果方可用 `partial` 收尾，余量不足时不签发后续游标。若连尾页也无法登记，Host 只能使用之前已登记、仍可验证的个案，说明覆盖中断。服务在执行及页登记前核对并预留余量，原子记录已用额度和已登记页。新读、新页和支出继续累计，同页重放仍受传输次数及时间制约。进入最后 2 秒后结束取证与重新准备。
5. 授权撤回、用途限制变更、相关版本失效或当前性不可确认时，整份准备停止继续取证及重放。合法调用者同键改请求沿用 `IDEMPOTENCY_PAYLOAD_MISMATCH`，错配游标为 `CURSOR_QUERY_MISMATCH`，不可见句柄统一 `NOT_FOUND_OR_NOT_VISIBLE`。授权、阻断或屏障失败时按 02 返回安全错误，执行到期为 `DEADLINE_EXCEEDED`，可见结果包单纯到期为 `BUNDLE_EXPIRED`。错误回执无正文、来源标识或新使用包，隐藏来源不得通过覆盖、诊断或计数透露。已登记的页即使响应丢失，也纳入现有失效和消费者清理。 [02 §2.2](../../docs/spec-v1/02-api-contract.md#22-通用-http-错误) · [02 §2.6](../../docs/spec-v1/02-api-contract.md#26-所有记忆正文读取的用途与失效追踪)

## 归纳与交付

关联 `REQ-REVIEW-003`、`REQ-REVIEW-005`、`REQ-REVIEW-006`，覆盖 `AC-REVIEW-003`、`AC-REVIEW-004`、`AC-REVIEW-005`、`AC-REVIEW-008`、`AC-REVIEW-009`。

1. 模型逐项判读已通过用途和授权门禁的材料，给出事件身份线索、本地事件日、情境、已实行的做法、用户自述结果及各字段的精确来源引用。没有结论的材料保留判读状态。程序校验候选是否覆盖冻结的可见材料、引用和主体是否可核验、日期是否可归窗及身份关联是否可信。已知格式的结构化事实按注册规则比对字段。输入中的原话只作为数据。格式和引用校验只能证明候选可核对，语义误判及漏判在离线金标准中单列。 [01 §5.2](../../docs/spec-v1/01-data-model.md#52-evidence_dependency发布和回溯的基础)
2. 程序从核验后的事件明细分组，生成覆盖状态、计数、相反结果、未知、冲突及各自引用。至少有两次可证明独立且发生于不同本地日期的事件，在可比情境中呈现同一可观察的做法或选择，才给出重复观察。做法与结果须有明确关联。一条可信的自述可以回顾为个案，注明当时的报告。若存在相反结果，说明观察混合，并列支持与反例。两次重复只支持本时间窗内有限观察，禁止推导普遍收益、因果效果或未记录事件。
3. 同场景有实际可选项且被选做法可核验时，可表述为「在这些可比记录里重复选择了……」。其余情况回顾实际做法或注明是当次要求。用户后续另有明确长期偏好表达，才沿可信来源与原 `remember` / `revise` 处理。 [04 §5.5](../../docs/spec-v1/04-evaluation-and-acceptance.md#55-记忆触发偏好与事件身份的固定变体)
4. 首版从已核验的结构化结果固定渲染主题、窗口、事件分组、计数、引用、必要反例与缺口。需调整表达时，只能选择允许的句式和事件引用，程序检查必有项和结论类型，数字直接由结果填入。这样也能阻断一个保留原数字却额外加入因果的候选。结构化结果未通过核验时，只呈现能独立核验的个案与缺口。正式统计沿产品能力处理。回顾结果随本次操作受控交付，后续回顾重新取证。 [02 §2.4–2.6](../../docs/spec-v1/02-api-contract.md#24-写回执与新鲜度)

示例为合成材料。6 日和 8 日两次出门均记录「前夜把钥匙放包里」，6 日说带齐，8 日说仍忘带门卡。10 日明确记载同样做法和出门，缺少结果。回答可呈现「这段记录里反复出现提前把钥匙放包里的做法。一次带齐、一次仍漏带门卡，还有一次没有记录结果。」各项可回看相应日期的证据。若 10 日只提到计划，或出门本身未经证实，只在可核验个案中按原语气回顾。

## 重新回顾与失效

关联 `REQ-REVIEW-004`、`REQ-REVIEW-005`，覆盖 `AC-REVIEW-006`、`AC-REVIEW-007`、`AC-REVIEW-008`。

| 事件 | 处理 |
| --- | --- |
| 同一请求重试 | 保持同一 operation、turn、准备版本、请求哈希、主题及窗口，使用已固定的前缀，仅复用仍有效的结果。失效或到期的旧 key 只回安全状态。原 operation 尚未结束且仍在原总期限内，清理、权限及剩余预算均允许时，才可沿同一 turn 保持原主题及窗口，用新准备版本和 key 固定新的已应用前缀。超过执行期限后，重新取证来自用户的新 operation。未知的模型执行或计费沿既有 invocation 核对。 |
| 用户再次请求同一主题 | 绑定新 turn 和请求身份，重新确认主题及窗口，按本次授权固定新的已应用前缀。纳入迟到来源、反例和已应用的修订，重新归并与判读。前次回答仅作为会话定位线索。 |
| 源更正、撤回、擦除或撤权 | 已交付正文、归纳支持和反例，以及影响分组、否定、计数或结论范围的材料，即使未出现在最终引文中，也要追踪至精确版本。已知相关 fence、已收到的失效回执或当前校验失败均阻断旧准备的模型、工具、交付、重放和自动注入。按原 changes、ACK/reset 清理受控副本，scope 的当前性可核验且满足 Host 清理准入后才允许重准备。 |
| 用户说明「这次结果其实不对」 | 新明确事实经已有可信输入路径处理。用户若明确更正已存在的来源或正式条目，须解析目标并走其对应修订合同。单纯否定本次总结时，可请用户指出理解有误的结论或证据并重新回顾。反馈不能替代更正或删除来源所需的证明。 |

内部枚举沿用 `read_result`，每批在交付前原子登记明细、精确依赖、用途和 `consumer_context`。成功空页或尾页的范围声明参与回答或覆盖判定时，同样登记固定范围、授权及可见代次、已应用屏障和尾页验证，作为可无来源引用的范围依赖。无正文的失败无需新使用包。响应丢失时已登记的包纳入清理。 [01 §9.2](../../docs/spec-v1/01-data-model.md#92-统一使用包-context_bundle-与消费依赖)

对已知产品或外部写动作，在各页取证、模型输入、依赖历史的工具调用、交付及重放前，按 `action_id` 检查全部相关持久 pending fence 并执行适用读屏障。状态 unknown 时继续阻断。已提交的动作须按对应 applied 回执或连续 barrier 关闭，确认未发送并已持久取消或取得权威终态未提交证明时按原合同关闭相应 fence。 [03 §3.3](../../docs/spec-v1/03-agent-sequences-and-recovery.md#33-更正与删除的跨系统边界)

生产 Host 在其发送边界内缓冲答复，在同一次发送准入中校验当前 authority、runtime epoch、相关 fence 及所有使用包，并将本次回复和受控重放登记为下游依赖。排队后的实际发送同样经该门禁。获知变化或校验失败后，阻断新发送并停止已开始交付中的剩余部分。MemoryService 的本地阻断与独立系统通知沿各自合同生效，已经送出且脱离控制的字节无法收回。交付和受控 GET/SSE 重放均须在最早的实际依赖包到期前通过在线校验。五分钟使用包 TTL 到期或已应用失效后，只返回安全状态。来源仍按其生命周期管理。已交付的回顾到期后，用户可再次发起回顾。过期、reset 或能力开关关闭后，消费者清理责任持续到可核对的 ACK/reset 或合同规定的终止证明。 [02 §12](../../docs/spec-v1/02-api-contract.md#12-bundle复核post-v1bundlesvalidate) · [03 §5.3](../../docs/spec-v1/03-agent-sequences-and-recovery.md#53-context-与补查使用-bundle)

宿主按既有 journal 和最小审计记录主题及策略版本、范围摘要、准备版本、受控引用、覆盖或拒用原因及模型开销。带依赖的回复仅按本次操作的交付与重放规则处理，后续题目需重新取证。审计默认只留获授权元数据，原话、完整 prompt 与正文缓存继续受现行保留和失效约束。 [01 §9.3](../../docs/spec-v1/01-data-model.md#93-审计和评测日志)

## 权衡、兼容和发布

- 首轮先比较按需归纳与同预算的普通相关历史召回。冻结主题规则、前缀、授权、主模型及证据篇幅，分别记录身份归并、覆盖、弃答、过度推断、引用忠实性、延迟、推理开销与用户任务收益。只有已核验的依据才可作为金标准，权限串线与失效正文重放是硬门禁。 [验收计划](test-plan.md) · [04 §6](../../docs/spec-v1/04-evaluation-and-acceptance.md#6-效果指标与发布门槛)
- C 试点以前置的授权、来源身份、full_lifecycle 使用包和清理机制可验为条件。启用时限定注册主题和受控宿主，关闭时回到原历史回答路径。现行来源、记忆和偏好合同可继续使用，本切片按需回顾不依赖新增持久规律表、接入前历史回填、定时任务或主动推荐。
- 后续若有足够收益，可另行评审按主体、主题和适用场景持久化规律，以及新证据触发复核、单条规律停用与当前头更新。持久化方案届时需说明稳定身份、版本、重算范围和清理，先按现行 C 扩展边界评审。 [06 §7.3](../../docs/spec-v1/06-history-ingestion-and-repair.md#73-定向派生复核c扩展)
