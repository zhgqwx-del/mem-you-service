# 单主题个人经验与规律回顾

- 变更 ID `002-single-topic-review`
- 阶段 C 扩展 · 设计基线已收尾，实施与试点验收待启动
- 已确认窗口 默认 14 个、最多 28 个已结束的本地自然日。
- 需求负责人 待项目确认
- 需求来源 用户明确指定「用户主动发起的单主题回顾」，确认窗口，并要求完成协议、预算、门槛和样本验证方案。本轮交付设计文档。

## 目标与范围

用户主动回顾一段个人经历时，可以看到自己试过的做法、记录过的结果及反例。证据足够时，回答指出有日期依据的重复行为或场景选择。证据不足时，仍可以回顾具体经历并说明缺口。试点使用「出门准备与漏带物品」，支持本人在同一主题内回顾经历、重复行为和场景选择。

本切片使用当前已摄取且获授权的来源。每次用户新发起回顾均重新取证。已有回答按宿主生命周期协议管理，受影响时停止使用或重放。跨会话可召回洞察、定期重算、主动提示、接入前聊天补采和跨主题归纳分属后续能力。显式偏好继续由既有用户确认与记忆修订路径处理。

## 本轮整体评审

| 发现 | 已补入草案的规则 |
| --- | --- |
| 只回核模型给出的引用，仍可能漏掉已读的反例 | 枚举范围、逐项判读、已核验事件、交付结果分开留踪。程序计算并保留必要反例。未完成判读或正文不能核验时回顾个案 |
| 取证按来源日期裁剪，可能漏掉首日前夜的准备和窗口结束后的迟记 | 以出门日归窗，允许可信关联的授权前夜证据。在授权前缀内接收的迟记按发生日纳入。未决冲突计一次，结果退出已知分母 |
| 旧键重新准备、产品变更未传播和最后一次校验后的发送边界不明确 | 区分原键重试、新准备和新用户请求。逐动作守住产品待定阻断和读取屏障。发送队列、受控回看和清理纳入宿主门禁 |
| 目标主题的记录密度缺少实证，单一盲评区间可能掩盖过度归纳或全弃答 | 以已确认的 14/28 日作为试点口径，实测可回答率及稀疏回顾。单独验可回答与不足样本、因果与引用错误、生命周期硬门禁、整体效用和资源预算 |

## 决策及待试点验证项

| 项目 | 可以先定 | 等试点验证 |
| --- | --- | --- |
| 主题与窗口 | 本人「出门准备与漏带物品」。默认最近 14 个已结束本地自然日，自定义 1 至 28 日。用户主动扩大才发起新回顾 | 授权记录能否覆盖目标人群及场景，14 日和用户选择 28 日时的可回答率、稀疏程度与使用体验 |
| 取证与失效 | 私有准备和分页的逻辑协议 v1、授权及快照绑定、证据和覆盖声明登记、读取屏障、调用重放与失效行为。到期回看仅显示状态及重新发起入口。 [内部取证协议](design.md#内部取证协议-v1) | 实际可用来源、投影裁剪后的覆盖率、取证与复核开销 |
| 初始资源上限 | 每次最多 512 条授权候选元数据、4 页、48 个来源版本、64 KiB、2 次模型调用及 12 秒执行期限。单 owner 跨宿主同时 1 次回顾。 [预算与计量](spec.md#试点资源预算) | 截断和超限比例、实际模型消耗、P95、货币成本及全试点并发。启用前根据开发数据和部署预算冻结资源验收线 |
| 初始启用门槛 | 适用 04 门槛和固定场景通过。足够证据正确归纳至少 90%，不足证据正确降级至少 95%。按 owner 等权效用至少 0.55，双侧 95% 区间下界高于 0.50。 [门槛与口径](test-plan.md#同预算效果对照) | 独立 owner 样本量、可覆盖分层及各分层阈值按开发资料冻结。用封存集验证收益与质量并判断能否启用 |

实施前按部署拓扑确认私有传输、索引方案、Host 门禁接入点和发布标识。初始资源上限和效果最低线是本草案的试点设计基线。后续若需调整，先在开发评估中记录依据及版本，再继续封存评测。授权、失效和断言的硬门禁持续适用。
